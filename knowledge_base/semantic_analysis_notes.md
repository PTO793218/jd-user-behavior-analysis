# 评论语义分析说明

## 为什么需要语义分析

原项目已经有评论词频分析，可以找出用户经常提到的词。但词频只能说明“被提到得多”，不能判断用户态度，也不能稳定识别负面原因。

例如“质量”出现频率高，可能是“质量很好”，也可能是“质量差”。仅靠词频无法区分这两种业务含义。因此第二版引入评论语义分析，让大模型对评论进行结构化标注。

## 分析流程

评论语义分析由离线脚本 `agent_app/semantic_analysis.py` 完成。流程如下：

1. 从 `jd_analysis_final.csv` 读取 `comment` 字段。
2. 清理空评论、“无评论”、“暂无评论”、“默认好评”等无效文本。
3. 对有效评论去重，生成 `comment_hash`。
4. 分批调用 DeepSeek/OpenAI-compatible API。
5. 输出逐条明细到 `comment_semantic_result.csv`。
6. 输出聚合统计到 `semantic_summary.csv`。
7. 再次运行时跳过已处理的 `comment_hash`，支持断点续跑。

## 当前样本口径

由于 API 调用会消耗预算，当前不是全量评论语义分析，而是在预算限制下完成的样本分析。

当前结果：

- 已分析去重评论样本：960 条。
- 正面：447 条。
- 负面：429 条。
- 中性：84 条。

回答评论语义相关问题时，必须使用“已分析样本”或“960 条去重评论样本”的表述，不能说“全量评论”。

## 输出字段解释

`sentiment` 表示整体情绪，只能是正面、中性、负面。

`sentiment_score` 表示情感分数，范围为 -1 到 1。越接近 1 越正面，越接近 -1 越负面。

`aspects` 表示评论涉及的业务方面，固定标签为质量、物流、价格、服务、包装、售后、体验。一条评论可以有多个方面标签。

`negative_reasons` 表示负面原因，只在负面或中性偏负评论中填写，例如疑似假货、质量差、包装破损、物流慢、客服态度差等。

## 当前主要发现

从当前 960 条样本看，评论情绪分布较为接近，正面 447 条，负面 429 条，中性 84 条。负面评论占比较高，说明评论样本中存在较明显的问题反馈。

从方面标签看，质量相关评论最多，说明质量是用户讨论最集中的主题。质量方面共有 705 条相关评论，其中负面 305 条，负面率约 43.26%。

从负面率看，售后、服务、包装的负面率更高。售后相关评论 57 条，其中负面 50 条，负面率约 87.72%；服务相关评论 148 条，其中负面 96 条，负面率约 64.86%；包装相关评论 91 条，其中负面 51 条，负面率约 56.04%。

因此，评论语义分析不能只看“负面数量”，还要同时看“负面率”。质量问题覆盖面大，售后和服务问题的负面倾向更强。

## 使用限制

评论语义分析结果受样本量、模型理解能力和评论文本质量影响。它适合用于发现问题方向和形成运营假设，不应直接作为最终业务决策的唯一依据。

如果用户询问当前数据无法支撑的问题，例如“所有用户是否都不满意售后”或“全量评论负面率是多少”，Agent 应明确说明当前只有 960 条样本语义结果，不能外推为全量结论。
